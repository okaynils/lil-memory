Your AI memory as a folder of Markdown files. Works with any model. No account, no cloud, no company in the middle.

lil memory is a small local MCP server. Every AI client you connect (Claude Desktop, Claude Code, Codex, ChatGPT and others) reads and writes the same memories. The memories are plain files in a folder you own, so you can read and edit them in Obsidian or any text editor.

Why lil memory

Most people now use more than one AI: Claude in the morning, a coding agent in the afternoon, ChatGPT on the go. Each one keeps its own memory, on its own company's servers, and none of them knows what the others learned. lil memory is one memory that all of them share, and it lives with you.

  • Yours, as plain files. One Markdown file per memory, in a folder you own. Read it, edit it, search it, sync it or put it in git. There is nothing to export and nothing to be locked into.
  • Every AI, the same memory. Claude Desktop, Claude Code, Codex, ChatGPT and any other MCP client can use it at the same time. Tell one of them something and the others know it too.
  • Obsidian is the interface. Memories are linked notes. Browse the graph, fix a memory by hand, and your AI sees the change within two seconds.
  • Small and boring on purpose. One small Python program with two dependencies. No account, no cloud, no API keys, no background service and no AI model of its own. The whole core is about 1,400 lines you can read in an afternoon. It starts in under half a second and searches 10,000 memories in about 10 ms.
  • An open format. The file format is written down in SPEC.md, so other tools can read and write your memories, and they outlive this project.

Basic Memory is the closest relative and a good project. If you want a fuller knowledge-management system, look at it. lil memory does less on purpose: six tools, a fixed file format with a written spec, and a permissive license.

When something else fits better

  • You only use one AI and are happy with it. Its built-in memory is less work.
  • You need search by meaning rather than by words. lil memory uses full-text search only; there are no embeddings.
  • You want one memory for a whole team. lil memory is built for one person.

Quickstart

You need uv. Then:

  1. Create the vault at ~/lil-memory: 
    uvx lil-memory init
  2. Connect a client (claude-desktop, claude-code or codex; for others see Connect your AI): 
    uvx lil-memory install claude-desktop
  3. Restart the client and talk to it:
    • "Remember that I prefer British spelling."
    • "Load my context for acme-site."

Run lil-memory open to explore and edit your memories in Obsidian. The first time, Obsidian asks you to pick the vault folder once ("Open folder as vault"); after that the command goes straight there. Without Obsidian, it opens the folder in your file manager. Run lil-memory doctor if something does not work.

Usage

Most of the time you do nothing. lil memory tells every connected AI to use it on its own:

  • When you start working on something, it looks up your preferences and that project's memories.
  • When you say something that should still matter next time, it saves it right away. "I don't like that, keep it shorter", "we use pnpm here" or "let's go with Postgres, it's what the team knows" each become a memory.
  • Saving happens quietly on the side. The conversation carries on as normal: say "I like nature" and it saves that, then talks about nature with you. It does not mention the memory; your client shows the tool call. Say "forget that" if it got it wrong.
  • Each memory gets a short, descriptive title and is linked to related memories, like notes in Obsidian. Say "my favorite team are the 49ers" and later "my favorite player is George Kittle": you get favorite-nfl-team.md and favorite-football-player.md, linked to each other in Obsidian's graph.
  • It does not save one-off requests, temporary details, its own guesses, or secrets such as passwords and keys.

The AI decides when to save; lil memory never reads your conversations itself. Most clients follow these instructions. If yours does not, add this line to its instruction file, such as CLAUDE.md or AGENTS.md:

Use the lil-memory tools on your own: recall my preferences and the current project when a task
starts, and remember preferences, corrections and decisions as soon as I state them.

You can also ask directly, in plain words:

  • Save something: "Remember that the acme-site deploys to Cloudflare."
  • Find something: "What do you know about my writing preferences?"
  • Pick up where you left off: "Load my context for acme-site." This loads your profile plus the latest memories for that project.
  • Change something: "Update that memory: we now deploy to Fly." The old version is kept, marked as superseded.
  • Remove something: "Forget the memory about my old address." It moves to the trash and can be restored by hand.

Edits you make in Obsidian show up in searches within about 2 seconds. To keep the vault somewhere else, pass --vault PATH or set $LIL_MEMORY_VAULT.
